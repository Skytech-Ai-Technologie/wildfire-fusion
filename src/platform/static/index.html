Read this before you trust a number

The LWIR half is a proxy

A plain RGB camera has no thermal sensor. The dual-stream model needs 6 channels (RGB + LWIR), so the LWIR half is filled with the grayscale proxy of the RGB frame — the same documented placeholder the training path uses on RGB-only datasets. It is not thermal data, and the thermal modality carries no independent information here.

One camera caps the fused mass

With a single modality the Dempster–Shafer mass is m(F) = r·π̂ ≤ r, and rc = 0.80 by default. So τ must sit below 0.80 for the alarm to be reachable at all — that is the framework behaving correctly, not a bug. A second camera or the simulated IIoT node gives a richer (and lower-banded) mass.

τ = 0.78 is the paper's number

It was calibrated for FPR < 2% on the authors' own validation set. Your camera, scene and class priors differ, so recalibrate on your data (src/calibrate_decisional.py) before treating an alarm as a detection claim.

Latency and rate

The loop runs at the capture rate you set. CPU inference is the bottleneck on a laptop; the readout shows the real measured latency and FPS so you can see what your machine actually sustains.
